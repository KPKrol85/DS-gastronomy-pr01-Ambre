# Ambre — Final Technical Front-End Audit

**Audit date:** 2026-10-26
**Completion/archive date:** 2026-10-30
**Status:** COMPLETED — all findings resolved and verified; archived
**Audited revision:** `9164f2c`

## 1. Scope and assessment

Final review of the eight-page Polish restaurant demonstration website: HTML, modular CSS, JavaScript, accessibility, responsive behavior, interactions, build/QA, SEO, PWA and Netlify configuration.

**Original assessment:** Ready with minor refinements. The architecture was appropriate for the portfolio scope. No P0, P1 or optional findings were identified; three P2 accessibility and progressive-enhancement findings required remediation.

## 2. Closed findings

### [P2-01] Dark-system fallback gives action labels insufficient contrast without JavaScript

- **Status:** COMPLETED — verified (Defect).
- **Resolution:** Corrected `.site-button` colors in the dark-system no-JavaScript fallback, preserving explicit themes, button variants and native actions.
- **Verification:** `qa:nojs` passed; minimum contrast reached 14.69:1 for the 404 link and 9.35:1 for the form button (previously 1.13:1 and 1.62:1). Theme E2E (6/6) and CSS lint passed.

### [P2-02] Mobile drawer traps keyboard focus while leaving background accessibility content exposed

- **Status:** COMPLETED — verified (Source-visible risk).
- **Resolution:** Added `aria-modal` and background `inert` isolation to the mobile drawer, preserving prior inert states, focus restoration, responsive closing and coexistence with the demonstration dialog.
- **Verification:** Mobile-navigation E2E (5/5), full E2E (65 scenarios) and accessibility scans (14) passed; Chromium accessibility-tree checks confirmed background isolation.

### [P2-03] JavaScript-only controls remain enabled in the native baseline

- **Status:** COMPLETED — verified (Defect).
- **Resolution:** Disabled filters, dish previews and theme controls until their handlers initialize; preserved visible content, layout stability and native navigation.
- **Verification:** `qa:nojs` passed across eight pages at 390/1280 px, confirming disabled, keyboard-inactive controls and accessible content. Menu (7/7), lightbox (13/13), gallery (6/6) and theme (6/6) regressions passed.

## 3. Final verification

- **Original audit (2026-10-26):** `qa:fast`, `img:verify`, E2E (64 scenarios), axe (14 scans), Service Worker regression, no-JavaScript checks and 96 layout checks passed. The filesystem build, full QA aggregate and Lighthouse were not run during the original audit.
- **Remediation (2026-10-27–29):** Focused regressions passed. `npm run build` (239 files), `qa:server` and `qa:service-worker` passed; `npm run qa` failed at ESLint in the dot-prefixed worktree, and separate Lighthouse runs scored 0.63–0.83 against the 0.85 Performance threshold.
- **Closure (2026-10-30):** The mobile-header layout-shift correction passed mobile-navigation E2E (5/5, eight pages) and `qa:nojs`; source and documentation checks passed. The full QA aggregate and Lighthouse were not rerun after this correction.

## 4. Limitations

- No passing full QA or Lighthouse result was recorded on the closure revision. The previous failures involved the ESLint worktree path and Lighthouse Performance under host CPU contention.
- Hosted Netlify behavior remained unverified (PH2-02 blocked): deployed revision, CSP/headers, redirects, form-provider receipt and production PWA behavior.
- Browser evidence was limited to Chromium; other engines, physical devices and manual screen-reader testing were not verified.
- The mobile no-JavaScript fallback depends on `(scripting: none)` support; unsupported browsers and failed bundle loading were not verified. Native date constraints cannot exclude Mondays without JavaScript.

## 5. Final assessment

**Findings:** 3/3 P2 resolved and verified; no open audit findings.
**Release readiness:** Not confirmed at closure pending a passing full quality gate and hosted verification.
**Senior rating:** 8/10 — original rating retained without reassessment.
