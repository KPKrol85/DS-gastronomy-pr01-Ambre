## 6. P2 — Minor refinements (resolved)

### [P2-01] Dark-system fallback gives action labels insufficient contrast without JavaScript

- **Status:** COMPLETED — implemented and verified.
- **Issue:** Without JavaScript and with a dark system preference, `data-theme` stayed absent: system tokens lightened the label ink while the button corrections required `html[data-theme="dark"]`, leaving the reservation submit at 1.62:1 (`#eef1f6` on `#fab204`) and the 404 recovery link at 1.13:1 (`#eef1f6` on white).
- **Resolution:** `css/components/buttons.css` applies the explicit-dark base surface, border and hover of `.site-button` under `prefers-color-scheme: dark` for `html:not([data-theme])`, wrapped in `:where()` so variant surfaces keep their precedence, and `.site-button--form` sets dark ink on amber (`var(--c-accent-ink, #1b1b1f)`). Explicit light/dark rules, theme initialization, `data-theme-ready`, native submission and 404 navigation are unchanged.
- **Verification:** `npm run qa:nojs` — PASS, including a new computed-color WCAG check without `data-theme` (rest/hover/active): recovery link 17.17/15.69/15.69:1 light and 15.92/14.69/14.69:1 dark, submit 9.35/10.01/10.01:1 under both preferences, with pointer-driven native submission and navigation. `npm run test:e2e:theme` (6/6), `npm run lint:css` and `git diff --check` — PASS; a computed-style comparison of all `.site-button` elements on eight pages showed changes only in the no-JavaScript dark state. Chromium only; focus-outline contrast and other button variants are outside the regression.

### [P2-02] Mobile drawer traps keyboard focus while leaving background accessibility content exposed

- **Status:** COMPLETED — implemented and verified.
- **Issue:** The open `#mobile-drawer` (`role="dialog"`) locked scrolling and trapped Tab, but declared no modal state and left the background non-inert; a Chromium accessibility-tree probe at 390 × 844 px still exposed the banner, main content and reservation controls.
- **Resolution:** `js/modules/nav.js` sets `aria-modal="true"` while the drawer is open and makes every other `<body>` child except the drawer and its dismissal overlay `inert`, saving each element's earlier state and restoring it before focus returns on every close path, including the 940 px breakpoint. The drawer declines to open while another dialog has already made it inert, so the demo-information dialog keeps its isolation and focus; initial focus, the Tab trap, focus restoration and the no-JavaScript fallback are unchanged.
- **Verification:** `npm run test:e2e:mobile-nav` — PASS (5/5), extended with modal-ARIA, background-inertness-against-baseline (including the already-inert closed demo dialog), rejected-focus and Chromium accessibility-tree assertions (only the unnamed overlay remains outside the dialog), plus pointer opening, link activation, repeated 939/940 px transitions and demo-dialog coexistence; it fails against the previous `nav.js`, and a probe showed `aria-modal` alone does not prune Chromium's tree. `npm run qa:nojs`, `npm run test:e2e:demo-legal` (4/4), the full `npm run test:e2e` aggregate (65 scenarios), `npm run qa:a11y` (14 scans), ESLint on the changed files and `git diff --check` — PASS. Chromium only; no manual screen-reader pass was performed.

### [P2-03] JavaScript-only controls remain enabled in the native baseline

- **Status:** COMPLETED — implemented and verified.
- **Issue:** Without JavaScript, the category filters on `index.html`, `menu.html` and `galeria.html`, the `.dish__thumb` preview buttons and the theme toggle on all eight pages stayed enabled keyboard stops, although only `tabs.js`, `lightbox.js` and `theme.js` provide their actions.
- **Resolution:** These buttons ship `disabled` and each module enables its own controls only after binding their handlers, independently of `no-js` removal. Disabled filters and the toggle are `visibility: hidden`, keeping their layout box so enabling them causes no load-time shift; disabled previews keep their visible `<picture>`, while dishes, gallery links, disclosures and navigation are unchanged.
- **Verification:** `npm run qa:nojs` — PASS, including a new eight-page check at 390/1280 px: no targeted control is enabled, focusable or a Tab stop, filters/toggle are absent from the Chromium accessibility tree and previews are exposed as disabled, while dishes and images stay visible, navigation and disclosures stay keyboard-reachable and gallery links open their images. `test:e2e:menu-details` (7/7), `test:e2e:lightbox` (13/13), `test:e2e:gallery-status` (6/6), `test:e2e:theme` (6/6), the other E2E suites, `qa:a11y`, `lint:css`, `qa:html`, `qa:csp` and `git diff --check` — PASS; ESLint passed on a copy outside the dot-path worktree. Chromium only; no manual screen-reader pass.
